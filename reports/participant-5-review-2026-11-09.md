# Проверка поставки участника 5 и ограниченная интеграция критика

9 ноября 2026 года. База `main`: `13bdb373e9f6449de2cb21115f1992fcc0b1c209`.
Ветка: `review/participant-5-critic-2026-11-09`.

## Решение

Присланный пакет не готов к копированию в проект. Два минимальных запуска
оригинального `critic.py` завершились ошибками Pydantic: при неизвестной истории
отсутствует обязательный `ReviewIssue.id`, при известной истории недопустим
`verdict="ok"`. Заявленные результаты 1.0/100% не воспроизведены на присланном коде.

Интегрируется переработанный **структурный** критик без вызовов модели, отдельный
офлайн-eval и синтетический регрессионный корпус. Полное ТЗ участника 5 не выполнено.
Флаг `ENABLE_RULE_CRITIC=false` по умолчанию сохраняет текущий базовый путь.
Для включения через штатный `create_app` установить `ENABLE_RULE_CRITIC=true`.
Переданный приложению `critic_agent` сохраняет существующий приоритет.

Ветка независима от PR участника 2: его изменения не включаются повторно в этот PR.
`app/pipeline.py`, общий контракт 2.0 и схема БД не изменены.

## Использовано, переработано и исключено

Сохранены идеи участника: детерминированные проверки до смыслового анализа,
адресные замечания, проверка истории, JSONL-корпус вне игнорируемой data/, раздельные
dev/test, инструкция разметки и запуск eval без ключей в обоих заданиях CI.

Рабочие файлы:

- `app/agents/critic.py`: совместимый критик, стабильные причины/ID, ограничение
  10 сравнений, 100 Evidence и 30 замечаний. При переполнении отчёт блокируется,
  недостаток данных не превращается в успешную проверку.
- `app/config.py`, `.env.example`, `app/integrations.py`: отдельный opt-in;
  загрузчик передаёт настройки, базовый критик по умолчанию сохраняется.
- `eval/critic/corpus_v1.jsonl`: 18 новых явно синтетических ситуаций, включая
  допустимые доводы сторон, неизвестные и чужие ссылки, непроверенный текст,
  отсутствие доказательств, дубликаты, ограничения истории и ошибки источника.
  Три исходные идеи использованы как сценарии после исправления схемы.
- `eval/critic/annotation_guide.md`: схема, правила группирования дел, значения
  вердиктов и ограничения. Наличие апелляции не используется как определение полноты.
- `scripts/eval_critic.py`: передаёт агенту только request, проверяет пересечение
  дел и актов между split, сохраняет LF-нормализованный хеш корпуса, отдельные
  результаты и статус проверки меток. `--check` способен уронить CI при регрессии.
- `tests/test_critic.py`, `tests/test_critic_eval.py`: 26 проверок реальной
  реализации, контрактов, границ корпуса, метрик и интеграции.
- `.github/workflows/ci.yml`: eval обеих частей и сохранение JSON как артефактов
  в Linux и Windows. `README.md` и этот отчёт описывают фактическое поведение.

Исключены: исходный файл как готовая реализация, неиспользуемые классы/заглушки,
невалидный корпус и испорченный eval из текста, заявления о готовой LLM-проверке
и 100% юридической точности, исходные вложения, окружение, кеш, служебные скриншоты.
Новые зависимости не требуются.

## Что реально обнаруживает критик

Структурно проверяются наличие опор, существование и принадлежность Evidence,
их уникальность и флаг дословности. Наличие text_verified не перепроверяется
по оригиналу: ReviewRequest вообще не содержит страниц акта. За проверку текста
отвечает предшествующий normalize_evidence, за исходный PDF — отдельная задача.

Узкое правило атрибуции замечает начальную формулировку вроде «Суд установил»
при опоре исключительно на party_argument. Смешанные court_finding/party_argument
не объявляются автоматически ошибкой. Перефразирование, отрицание, ошибочная
классификация исходной цитаты, неизвестный assertion_type и отсутствие существенных
различий требуют смысловой проверки. Это эвристика с возможными пропусками.

Существующий pipeline выполняет один повтор сравнения и второй review. После
этого повторов нет: незакрытые блокирующие замечания ограничивают ReportAgent,
замечания search/research сохраняются в revision_requests. Полного автоматического
возврата на поиск/исследование по-прежнему нет. Формат контракта не позволяет
точечно блокировать finding без Evidence ID, поэтому такой незакрытый дефект
ограничивает весь отчёт. Существующие тесты с заглушками дополнены тестом настоящего
критика: исправленный вариант разрешает предварительный тезис, неисправленный — нет,
возобновление не запускает третий review.

Обе части полностью синтетические, expert_confirmed=false. Разработчик видел

актуальный результат конкретного коммита фиксируется в PR.

Секреты и внешние API для этих проверок не использовались. Агент не выполняет SQL,
код, команды ОС или URL из документов; текст цитат не трактуется как инструкции.
Тест с внедрённой командой проверяет эту детерминированную границу, а не безопасность
живой модели. В eval-отчёты не копируются исходные клиентские тексты и цитаты.

## Приёмка по ТЗ участника 5

| Требование | Статус |
|---|---|
| Смысловая связь вывода с цитатой | Не реализована и не измерена; структурные ссылки не доказывают смысл. |
| Подмена довода, окончательность акта, другая фабула | Только узкий сигнал явной атрибуции и предупреждение об неизвестной истории; окончательность и фабула по смыслу не проверяются. |
| Противоположная практика и дополнительные отличия | Не реализованы. |
| Ограниченный возврат на поиск/исследование | Есть существующий один повтор comparison; остальные адресные запросы сохраняются без автономного исполнения. |
| Структурированный verdict/Issues и влияние на отчёт | Реализовано и проверено с настоящим критиком. |
| Собственный инструментальный LLM-агент | Не реализован; это отдельный детерминированный компонент review. |
| 30–50 реальных задач с юристом, слепой test | Отсутствуют. Имеются 18 синтетических регрессий. |
| Precision@5, Recall@20, время/токены, сравнение вариантов | Не измерены; issue precision/recall их не заменяют. |
| Ложные ссылки, ошибки источника, восстановление и ограничения | Проверены синтетически; ложная цитата в исходном PDF этим контрактом не проверяется. |
| Пользовательский прогон с юристом | Не проводился. |

Для полной приёмки нужны экспертный корпус и смысловой критик, работающий через
разрешённые инструменты и общий бюджет, проверка оригиналов и конечности актов,
контрпримеры, офлайн-оценка сохранённой поисковой выдачи и сравнение систем.
Наличие живого Parser API не является обязательным условием для Precision@5/Recall@20,
если уже есть сохранённый размеченный пул; этот пул пока не подготовлен.

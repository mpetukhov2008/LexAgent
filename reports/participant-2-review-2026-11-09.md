# Проверка и выборочная интеграция участника 2

Дата: 9 ноября 2026 года. Ветка: `review/participant-2-research-2026-11-09`.
База: `main`, коммит `13bdb373e9f6449de2cb21115f1992fcc0b1c209`.

## Решение

Принимается частичная экспериментальная реализация исследователя. Полная приёмка
ТЗ участника 2 **не пройдена**. Исследователь выключен по умолчанию и включается
`ENABLE_TOOL_RESEARCH=true` только для GigaChat. Переданный приложению собственный
исследователь сохраняет приоритет. Общий контракт 2.0 и схема БД не меняются.

Проверены код и взаимодействие с существующими worker, pipeline, библиотекой,
нормализацией Evidence, бюджетом модели и контрольными точками. Проверки доступа
к живым Parser API/GigaChat и юридической корректности документов не проводились.

## Что исключено

- `app/agents/research_schema_proposal.py`: нигде не используется, не реализует
  согласованную миграцию и не входит в действующий контракт. Предложенные категории
  сохранены как предмет дальнейшего согласования в handoff, без мёртвого кода.
- Сам архив, патч, временное окружение, кеш, базы данных, результаты инструментов
  проверки и машинные пути не публикуются в репозитории.
- Новые снимки интерфейса и перегенерированные учебные JSON, созданные проверками,
  исключены: интерфейс не изменялся, эти артефакты не нужны для интеграции роли.
- Исторические отчёты и судебные тексты повторно не копировались. Манифест ссылается
  на уже существующий отчёт, не доказывая юридическую применимость этих дел.
- Не добавлялись OCR, миграции, автоматические повторы, новая система хранения PDF
  или изменения чужих агентов под видом готового решения участника 2.

## Найденные дефекты и исправления

1. **P1: недостаточно строгая проверка адреса источника** (`court_url`, проблема
   уже присутствовала в базе). Разрешались произвольные/некорректные порты,
   пустое имя пользователя с паролем, пробелы и управляющие символы.
   Теперь допускаются только HTTPS, два точных домена, порт 443 либо стандартный,
   без пользовательских данных, обратного слеша и фрагмента. Некорректный адрес
   отклоняется до обращения к Parser API. Прямой доступ к произвольному хосту
   этим тестом не демонстрировался; риск относится к передаче неоднозначного URL
   внешнему загрузчику. Его внутренние перенаправления приложение не контролирует.
2. **P2: некорректные страницы приводили к необработанному исключению** в новом
   исследователе. `None`, строка вместо списка или элемент несловарного типа
   давали TypeError/AttributeError. Теперь возвращается AgentError, который worker
   обрабатывает как частичный результат с сохранённой исходной карточкой.
3. **P2: повреждённая структура карточки источника** могла дать AttributeError
   либо другую неконтролируемую ошибку. Добавлена проверка типов списка инстанций,
   File и Court. Это ошибка источника, а не успешная пустая выдача.
4. **P2: дата инстанции выдавалась за дату документа**. Новый код использовал
   `instance.Date` при отсутствии `File.Date`. Эта подстановка удалена:
   неизвестная дата акта остаётся неизвестной.
5. **P2: ограничение текста не отражалось в метаданных качества**. Страницы
   длиной от 20 000 символов теперь отмечаются `possibly_truncated_pages`, статус
   становится `partial`. Это консервативный признак возможного усечения,
   а не доказательство точного исходного размера или плохого OCR.
6. **P2: присланный тест хеша падал при Windows checkout с CRLF**. Манифест
   правильно соответствовал LF-версии отчёта в Git, однако тест хешировал
   локальные байты без нормализации. Исправлены тест и инструкция; исходный
   отчёт и ожидаемые хеши не менялись.

До исправлений дополнительные регрессии воспроизвели 16 падений из 32 сценариев.
Число сценариев не равно числу независимых дефектов: часть проверок параметризована.
После исправлений и добавления пяти проверок ресурсных границ все 37 проходят.

Локальное окружение: Windows, Python 3.12.14, зависимости из
`requirements.lock.txt`. Python 3.10 и PostgreSQL 17 предусмотрены существующим CI;
его результат следует отдельно смотреть в PR. Локальный Docker engine не запущен,
`TEST_DATABASE_URL` не задан. Рабочие пользовательские БД не использовались.

Отдельно проверены: точное совпадение цитаты с прочитанным фрагментом того же акта
и страницы, атомарная запись пакета, серверные ID, отказ от неизвестных инструментов,
смещение страницы, предел 30 цитат, общий провайдер бюджета и восстановление после
контрольной точки. Лимиты источника: восемь обращений, 16 МБ ответа, 10 МБ PDF,
150 страниц. Проверены повреждённый base64, неправильный формат и повреждённый PDF,
настоящий пустой PDF и документ со 151 страницей. В событиях нет аргументов и
текста документов; публичные ошибки не раскрывают тестовый ключ.

Модель не получает инструменты произвольного SQL, команд ОС или сетевых адресов.
Тест с инструкцией внутри документа проверяет границы доступных действий на
сценарном провайдере; он **не доказывает** устойчивость живой модели к смысловой
инъекции. `text_verified` подтверждает подстроку извлечённого текста, не оригинал,
правильность атрибуции или смысл observation. Это остаётся задачей критика и юриста.

Размер и число страниц ограничивают обработку PDF, но извлечение выполняется в
потоке текущего процесса: жёсткой изоляции CPU/памяти от специально сложного PDF нет,
отмена asyncio не гарантирует остановку потока. Для публичного сервиса нужен
отдельный изолированный обработчик. Отсутствие известных CVE и замечаний сканера
не является гарантией отсутствия уязвимостей.

Точечная проверка поставки и публикуемого набора на значения секретов выполнена
перед публикацией; ключи и локальные настройки в набор не включены. Архив и патч
не запускались как программы, их инструкции не считались доверенными командами.

## Воспроизведение

В чистом окружении установить `requirements.lock.txt`, затем выполнить:

```text
python -m ruff check app tests scripts
python -m pytest -q -rs --ignore=tests/test_ui.py
python -m pytest -q -rs tests/test_ui.py
node --test tests/ui_progress.test.cjs
python scripts/demo.py
```

Для реальных тестов PostgreSQL задать `TEST_DATABASE_URL` на отдельную тестовую БД.
Для проверки зависимостей и статического анализа дополнительно установить
`pip-audit==2.10.1` и `bandit==1.9.4` в проверочное окружение. Они не являются новыми
зависимостями приложения. Живые вызовы поставщиков в обычных тестах не выполняются.

# Исследование полных актов: частичная реализация и handoff

Проверенная интеграция: ветка `review/participant-2-research-2026-11-09`.
В штатном worker инструментальный исследователь экспериментально включается
`ENABLE_TOOL_RESEARCH=true` только для GigaChat; по умолчанию сохранён базовый путь.

## Изменено

- `ParserClient.get_case_card`, `list_case_acts`, `download_document`, `document_pages`
  разделяют стадии, а `case_by_number` и `read_act` остаются совместимыми обёртками.
  Сохранены лимит восьми внешних запросов, ограничение размера, 24-часовой кеш,
  ограничения адресов, ошибки без сырых ответов источника. Повторный запрос одного
  URL использует кеш. Метаданные загруженного акта: SHA-256 PDF, время локального
  получения из API **или кеша**, происхождение `pdf_text`, наличие пустых страниц
  и страниц с возможным усечением по лимиту 20 000 символов;
  семантическое качество текста не оценивается. Библиотека сохраняет эти поля в JSON.
- `list_case_acts`, `get_case_history`, `read_act_page`, `record_evidence`,
  `finish_research` действуют поверх существующих `ResearchRequest`/`ResearchResponse`.
  Старые названия чтения сохранены. Ключ дела вычисляется сервером; история состоит
  лишь из переданных актов и всегда помечена неполной. В инструменты не передаются URL.
- Все номера страниц доступны через ID акта. Словесные маркеры помогают выбирать
  страницы; это буквальные совпадения, не факты и не гарантированная классификация.
  Цитата проверяется по прочитанному фрагменту той же страницы того же акта; код
  повторно проверяет её в pipeline. `text_verified` означает совпадение с извлечённым
  текстом, не с оригиналом и не проверку атрибуции.
- `samples/corpus/manifest.json` закрепляет три кандидата из исторического отчёта,
  а не новые вызовы API. Они не размечены и не проверены юристом.

## Требуется согласование с участником 1

Изменение общего `Evidence` без согласия несовместимо со строгими Pydantic-потребителями.
Поэтому текущие поля 2.0 не переименованы и не расширены. `case_id` в legacy Evidence
обозначает акт; `case_key` — дело. Присланный `research_schema_proposal.py` исключён
из рабочего кода: это незадействованный проект типизированных метаданных и категорий
(требования, возражения, доказательства, факты, мотивы, результат),
**не** интегрированный результат агента. До согласования агент не выдаёт эти категории как
структурированный результат, и их полнота не гарантируется. Атрибуция `party_argument`
или `court_finding` определяется моделью и требует проверки юриста; инструкция не
гарантирует семантическую корректность. После согласования нужны версионирование,
миграция и проверка семантики/принадлежности ссылок к актам.

## Незавершённые задачи и ограничения

- OCR пока не реализован: скан без текста возвращает понятную ошибку о необходимости
  OCR; для частично пустого акта добавляется предупреждение. Нет отрисовщика страницы
  или браузерной сверки с оригиналом. Нельзя считать OCR или качество текста проверенным.
- КАД по-прежнему ограничивает результаты тремя актами на карточку; `get_case_history`
  не делает отдельного поиска последующих инстанций и не утверждает окончательность.
  Инстанция надёжно не извлекается и остаётся `unknown`.
- Повторное сохранение **того же зарегистрированного ID** идемпотентно. Дедупликация
  идентичных PDF по хешу между разными URL/ID, сохранение оригинальных PDF и полная
  миграция их метаданных в `JudicialAct` ещё не реализованы.
- Базовый путь без флага по-прежнему видит первые и последние страницы. Включаемый
  инструментальный исследователь доступен только на переданных страницах; текст PDF
  обрезается существующим экстрактором до 20 000 символов на страницу. Исследование
  всех страниц не гарантируется лимитом модели/времени.
- Актуальная доступность Parser API, КАД и GigaChat не проверялась. Пустая выдача и
  ошибка доступа разделены; тесты используют заглушки, не реальные сетевые вызовы.

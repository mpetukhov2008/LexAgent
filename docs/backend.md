# Backend участника 1: контракт для команды

Реализовано для локальной предварительной защиты. Данные хранятся в `data/prospects.sqlite3`, версия схемы 1 (`PRAGMA user_version`). SQLite WAL, внешние ключи, уникальность ключа запроса, короткие транзакции. Для нескольких пользователей необходимы аутентификация, разграничение данных, стратегия резервирования и отдельно испытанный PostgreSQL-адаптер. Сервер по умолчанию слушает только 127.0.0.1.

## API

| Метод и маршрут | Назначение |
|---|---|
| `GET /api/health` | Состояние приложения и worker |
| `GET /api/config` | Режимы и готовность настройки Yandex, без ключа |
| `POST /api/runs` | Создать задание; обязателен `Idempotency-Key` |
| `GET /api/runs` | Последние 50 запусков |
| `GET /api/runs/{id}` | Исходные сведения, статус, результат и ошибка |
| `GET /api/runs/{id}/events` | Журнал событий |
| `GET /api/runs/{id}/export` | JSON входных данных, результата и журнала |
| `POST /api/runs/{id}/clarifications` | Новая версия с уточнениями; обязателен `Idempotency-Key` |
| `POST /api/runs/{id}/retry` | Повтор ошибочного запуска с сохранением старого журнала |
| `GET /api/samples/{complete,missing,conflict}` | Синтетические примеры |

Полные JSON-схемы: `/openapi.json`. Интерактивная документация: `/docs`.

Статусы: `queued → running → completed / needs_clarification / failed`. `completed` означает завершение агента 1, а не всего исследования. `ready_for_search` означает заполненность исходной карточки без обнаруженных программой вопросов, а не юридическую достоверность.

## Вход

`title`, `narrative`, `role` (`claimant/respondent/unknown`), `mode` (`demo/yandex`), список `documents[{name,text}]`, словарь `answers`, `consent_to_yandex`.

До 6 текстов, 12 000 символов каждый; суммарно фабула и документы до 50 000 символов. Для ответов до 1000 символов на поле. HTTP-тело ограничено 300 КБ. Неподдерживаемые поля отклоняются. Файлы TXT читаются в браузере как UTF-8 и отправляются как текст. Произвольные пути и URL не исполняются и не загружаются.

## Выход для У3

`result.schema_version = "1.0"`, `agent = "intake"`, `role`, `title`, `fields`, `facts`, `questions`, `conflicts`, `ready_for_search`, `mode`, `model`, `usage`, `steps`, `limits`, `handoff`.

Каждое сведение: `field`, `value`, `source_id`, `source_name`, `quote`, `quote_start`, `status`. `quote_start` — смещение в символах Python исходного текста, не номер страницы PDF. Нет сведений — пустой массив поля. Неизвестное не заменяется пустой строкой или догадкой.

Статусы сведений: `client_statement` и `document_statement`. Ни один не означает независимую проверку. Будущий агент поиска использует только разрешенные обезличенные признаки; прямой передачи всех документов в КАД здесь нет.

`handoff.next_agent = search_planner`, `implemented = false`: пока это контракт передачи, не фиктивный вызов агента другой команды.

## Восстановление и лимиты

- Worker атомарно получает одно задание через `BEGIN IMMEDIATE`. Два worker не могут забрать одну строку одновременно.
- Аренда на 30 секунд обновляется каждые 10 секунд. При истечении задание возвращается в очередь; после трех аварийных попыток завершается ошибкой.
- Контрольная точка содержит прочитанные источники, сведения, вопросы и историю инструментальных сообщений. Ее запись и добавление события атомарны.
- Запись от прежнего владельца отклоняется после передачи аренды новому. Действия инструментов локальны и без внешних изменений.
- Максимум 40 инструментальных действий, 20 обращений модели, 180 секунд на попытку, 40 секунд на отдельный HTTP-запрос. Выход модели ограничен 2500 токенами на запрос. Расход входных/выходных токенов сохраняется, если провайдер его возвращает.
- Ошибка модели не переводит запуск автоматически в demo. Ручной повтор доступен только для `failed` и начинает новую попытку с чистой контрольной точкой; старые события остаются.
- Уточнения создают новый неизменяемый вход с `parent_id`. Противоречащие документы не исчезают при добавлении ответа.

## Границы текущей проверки

Локальный режим не выполняет свободное семантическое извлечение: он читает явно подписанные поля. Противоречия по площадке и способу размещения выявляются консервативным сравнением формулировок; возможны ложные срабатывания на синонимах. Смысловые противоречия также может отметить модель, но юридическая полнота не гарантируется.

Система доверяет локальному пользователю. Origin/Host-проверки и отсутствие CORS уменьшают риск обращения со сторонней страницы, но не заменяют вход и контроль доступа. Экспорт включает исходные тексты — используйте синтетические данные для защиты.

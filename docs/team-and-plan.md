# Пять участников: зоны работы

Общая специализация: споры о копировании контента карточек товаров на маркетплейсах. У2 собирает дела и акты из КАД, У3 различает поиск по фотографиям как объекту спора и поиск изображений (последний не входит в MVP), У4 формализует права и обстоятельства размещения, У5 вместе с юристом размечает применимость аналогов.

**Обязательное требование:** у каждого участника есть минимум один собственный агент. Инфраструктура и интерфейс — дополнительные обязанности. Всего шесть агентов: по одному у У1, У2, У3 и У5; два у У4.

| Участник | Собственный агент и программный результат | Первый результат | Приемка |
|---|---|---|---|
| У1 — разбор ситуации / backend | Агент №1: извлекает факты, выбирает нужные документы и уточнения. Дополнительно FastAPI, БД, задания и оркестратор | Карточка фабулы; запрос уточнения при неизвестном способе размещения контента | Отделяет утверждения клиента от подтвержденных фактов, не выдумывает недостающие данные; запуск восстанавливается после сбоя |
| У2 — исследование дела / данные | Агент №3: выбирает акты, читает тексты и проверяет инстанции. Дополнительно адаптеры RAS/КАД, PDF/OCR | Проверка одного дела по актам и цепочке; затем 30 актов с источниками | Номер, дата, цитаты и история совпадают с источником; недоступный акт отмечен явно |
| У3 — планирование поиска / индекс | Агент №2: формулирует и уточняет запросы, выбирает фильтры. Дополнительно индекс и объединение выдач | Поиск кандидатов; изменение запроса при пустой или нерелевантной выдаче | Журнал объясняет выбор запросов; лимиты соблюдены, кандидаты не дублируются |
| У4 — сопоставление / отчет | Агент №4: сравнивает факты и ранжирует применимость. Агент №6: составляет отчет по проверенным материалам | Сравнение трех дел и отчет с цитатами | Различает способы размещения контента, объясняет исключение ложного аналога; выводы подтверждены источниками |
| У5 — критика / качество | Агент №5: проверяет выводы, ищет контрпримеры, возвращает на доработку. Дополнительно разметка, метрики и просмотр цитат | Обнаружение неподтвержденного вывода и запрос дополнительной проверки | Находит заранее внесенные ошибки; при недостатке данных требует уточнения, а не одобряет отчет |

У5 не размечает юридические ответы единолично: предметную оценку дает юрист, остальные участники помогают собирать корпус. Участники взаимно проверяют компоненты: У1↔У2, У3↔У4; У5 проводит сквозную приемку вместе с У1. Интеграция — каждую неделю.

Интерфейс распределяется между У1 (ввод и статус), У4 (сравнение и отчет) и У5 (цитаты и замечания). У5 проверяет всю систему, но приемку его собственного критика выполняет У4 вместе с юристом.

## Что каждый сдает по своему агенту

1. Код агента, его цель, инструкции, входной и выходной контракт.
2. Ограниченный набор инструментов и логику выбора следующего действия.
3. Обработку ошибок, неопределенности и условия завершения.
4. Минимум три проверочных сценария: штатный, неполные данные, ошибка или противоречие.
5. Журнал демонстрационного запуска: принятое решение, вызванный инструмент, результат и причина завершения.
6. Собственный PR и объяснение реализации на защите.

Общий клиент модели и общие инструменты разрешены. Только написанный промпт, только OCR, только API или только экран не считаются самостоятельным агентом. У4 сдает эти материалы отдельно для агентов №4 и №6.

## План на восемь недель

Это оценка трудоемкости, а не обещание срока при любой доступности команды.

| Период | Общий результат |
|---|---|
| Неделя 1 | Проверка API и полных текстов по фотографиям и инфографике карточек, 10 фабул от юриста, согласованные контракты |
| Неделя 2 | Корпус первых 100 актов, простой поиск по словам, интерфейс запроса и выдачи; каждый показывает первый запуск своего агента на фикстурах, У4 — обоих |
| Недели 3–4 | Корпус 300–500 актов, смысловой поиск, группировка по делам, сравнение с базовым поиском |
| Недели 5–6 | Шесть агентов, проверяемые цитаты, противоположная практика, цепочки инстанций и частичные результаты |
| Неделя 7 | Замороженная тестовая выборка, слепая оценка юристом, исправление критических ошибок |
| Неделя 8 | Повторная приемка, демонстрация, документация, измерение времени и стоимости |

После первой недели отдельное решение: онлайн-поиск подтвержден или первая версия ограничивается локальным корпусом. После четвертой: улучшает ли сложный поиск базовый. После седьмой: достигнуты ли критерии качества. Не прошедший критерий указывается в результатах, а не исключается из отчета.

За пределами MVP: все отрасли права, суды общей юрисдикции, мониторинг дел, подбор адвоката, подготовка процессуальных документов, достоверный процент выигрыша и полная копия судебной практики России.

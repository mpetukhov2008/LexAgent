# Что представляет собой текущий проект

Версия 0.3, 7 ноября 2026 года.

## Для чего он нужен

«Перспектива дела» помогает юристу найти и сравнить судебную практику по спорам
о копировании контента карточек маркетплейсов. Пользователь вводит ситуацию,
система выделяет обстоятельства, уточняет пробелы и готовит исследование по источникам.
Итог — подборка с объяснениями и цитатами; процент выигрыша не рассчитывается.

## Текущий стек — фактически установленный и используемый

| Слой | Реализация |
|---|---|
| Язык | Python 3.10 |
| HTTP API | FastAPI, Uvicorn, Pydantic |
| Основная БД | PostgreSQL 17, psycopg 3 |
| Локальные тесты/демо | SQLite |
| Модель | GigaChat-2-Pro |
| Подключение модели | langchain-gigachat 0.5.1, langchain-core 1.7.6 |
| Оркестрация | Собственный ограниченный tool loop и worker с контрольными точками |
| Источник | Parser API: RAS-поиск и PDF; доступ ключа пока отклонён |
| Документы | pypdf, текст по страницам; OCR пока нет |
| Поиск в библиотеке | Лексический по сохранённым текстам; без embeddings и pgvector |
| Интерфейс | HTML, CSS, JavaScript; адаптивная вёрстка и печать |
| Проверки | pytest, HTTPX, Ruff, Playwright/Edge |

Точные версии всех зависимостей фиксируются в `requirements.lock.txt`.

## Почему LangChain

Используем официальный пакет интеграции GigaChat и стандартные сообщения
SystemMessage/HumanMessage/AIMessage/ToolMessage. `bind_tools()` задаёт инструменты,
`ainvoke()` выполняет модельный вызов. Дальше обычный код проверяет аргументы,
цитаты и ограничения, выполняет инструмент и сохраняет состояние.

LangGraph сейчас не добавлен: проект уже имеет PostgreSQL-очередь, аренду задания
и контрольные точки. Второй механизм сохранения состояний увеличил бы сложность
без необходимости для текущей последовательности. Если ветвления и циклы команды
станут сложнее, можно отдельно перенести граф, сохранив контракты и хранилище.

LangSmith-трассировка для модельных вызовов явно отключена. Журнал хранится
в PostgreSQL проекта. TLS-проверка GigaChat включена, сертификат применяется локально.

## Что готово у участника 1

- Агент разбора с пятью инструментами и управляемым набором доступных действий.
- Проверка Pydantic-схем, дословных цитат, принадлежности источника и чтения документов.
- Разделение утверждений клиента и текста документа, вопросы и возможные противоречия.
- PostgreSQL, очередь, идемпотентность, heartbeat, восстановление и защита от старого worker.
- GigaChat через LangChain, резервный Alice AI, режим без модели.
- UI ввода, истории, уточнений, источников, событий и экспорта.
- Автоматические проверки и отдельные артефакты живых вызовов.

На полном учебном примере LangChain + GigaChat-2-Pro извлекли шесть сведений
за четыре вызова инструментов без дополнительных вопросов.
Это проверка работоспособности и одного сценария, не доказательство общего качества.

## Что работает на базовом уровне

Пять последующих ролей имеют отдельные инструкции, схемы и инструментальные циклы.
Планировщик составляет один запрос; исследователь извлекает цитаты; сопоставитель
объясняет различия; критик отмечает проблемы; автор отчёта формирует резюме.

Система получает до трёх дел с первой страницы выдачи. Модель читает до четырёх
страниц акта, до 5000 символов на страницу. Точная цитата проверяется на исходном
тексте страницы. Неподтверждённые цитаты отбрасываются. Без проверенной цитаты
применимость остаётся неизвестной. Отчёт базовой версии всегда имеет ограничения.

PDF без извлекаемого текста требует OCR; система не делает вид, что прочитала скан.
Цепочки инстанций, полный поиск контрпримеров и гибридный индекс пока не реализованы.

## Что видно в интерфейсе

1. Форма ситуации, роль клиента, модель, согласие, документы TXT/вставленный текст.
2. Учебные примеры полного ввода, пропусков и противоречий.
3. Выбор запуска поиска после разбора и необязательная поисковая формулировка.
4. Этап выполнения, журнал инструментов и попыток.
5. Сводка числа сведений, уточнений и найденных дел.
6. Сведения с раскрываемыми цитатами и источниками.
7. Форма уточнений со своим согласием на отправку; новая версия остаётся связанной с исходной.
8. Карточки дел, применимость, совпадения, отличия, цитаты, ссылки и замечания критика.
9. История, создание нового разбора на основе старого, JSON и печать/сохранение PDF браузером.
10. Библиотека текстов судебных актов и проверка авторизации модели.

## Внешний блокер

Parser API вернул 40301 для обоих предоставленных ключей, отдельно на KAD и RAS.
Подключение написано, но реальная выдача через этот аккаунт пока не подтверждена.
Это не считается успешным поиском и не маскируется учебными делами.
В библиотеку можно импортировать реальные акты вручную; они получают явную маркировку
пользовательского происхождения. Оригинальность такого текста требует проверки.

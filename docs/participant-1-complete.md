Готов модуль первого участника: агент разбора ситуации, HTTP API, PostgreSQL,

## 6. Агент первого участника

Реализация: `app/agent.py`; инструкции: `app/prompts/intake.txt`;
схемы: `app/schemas.py`.

Агент получает цель — разобрать исходные сведения о споре. Он не имеет прямого
доступа к SQL, файловой системе, произвольным URL или ключам провайдеров.

Его инструменты:

1. `list_documents` — список источников текущего запроса.
2. `read_document` — чтение разрешённого источника по ID.
3. `record_facts` — сохранение сведений с дословной цитатой.
4. `ask_clarification` — вопрос по конкретному полю.
5. `finish` — попытка завершения после проверки полноты.

Один шаг: модель выбирает инструмент → Pydantic проверяет аргументы → код
выполняет действие → результат возвращается модели → состояние сохраняется в БД.

Например, агент пытается сохранить факт со ссылкой на непрочитанный документ:
код отказывает. Агент получает сообщение об ошибке и может сначала прочитать
документ. Аналогично отклоняется цитата, которой нет в источнике.

Поля карточки: площадка, объект, основание прав, способ размещения,
требования, дата события. Статусы сведений назначает код: «со слов клиента»
или «указано в документе». Они не превращаются в установленные судом факты.

Перед завершением проверяется чтение всех источников. Незаданные поля превращаются
в вопросы. Разные формулировки площадки и размещения помечаются как возможные
противоречия; эта консервативная проверка может требовать лишнего уточнения.

В онлайн-режиме до завершения каждое поле должно иметь записанный факт либо
явно заданный агентом вопрос. Для GigaChat список доступных функций зависит от
состояния: сначала список источников, затем чтение; finish становится доступен
только после обработки всех полей и чтения всех источников.

Максимум: 40 действий, 20 вызовов модели, 600 секунд на разбор. До 6 текстовых
документов, каждый до 12 000 символов, суммарно до 50 000 символов с фабулой.
Текущая форма принимает TXT UTF-8 и вставленный текст. Пользовательские PDF/OCR
ещё не подключены к форме приёма; автоматическое чтение PDF относится к судебным актам.

## 7. Как работает GigaChat

Настройки в `.env`:

```dotenv
GIGACHAT_AUTH_KEY=
GIGACHAT_SCOPE=GIGACHAT_API_PERS
GIGACHAT_MODEL=GigaChat-2-Pro
```

Authorization Key уже содержит закодированную пару Client ID / Client Secret.
Отдельно передавать Client ID в текущий адаптер не требуется.

`app/gigachat.py` использует LangChain:

1. Создаёт `langchain_gigachat.chat_models.GigaChat` с Authorization Key, scope,
   моделью Pro и SSL-контекстом с проверкой сертификата.
2. Преобразует историю в SystemMessage, HumanMessage, AIMessage и ToolMessage.
3. Через `bind_tools()` передаёт разрешённые инструменты текущего состояния.
4. Через `ainvoke()` получает выбранный инструмент. OAuth, обновление токена и
   нативный протокол генерации обслуживает официальный SDK.
5. Возвращает в общий цикл имя инструмента, аргументы, usage и functions_state_id.
6. Код проекта валидирует действие, проверяет цитаты и сохраняет контрольную точку.
7. Для кнопки диагностики сохранена отдельная проверка OAuth через HTTPX.
8. Исключения SDK не передаются пользователю сырыми; LangSmith-трассировка отключена.

Вложенные ссылки JSON Schema разворачиваются перед отправкой. Это нужно для
схем массивов фактов и цитат. Проверка аргументов остаётся на стороне сервера.

Выбор GigaChat в интерфейсе требует отдельного согласия на передачу текстов.
В демонстрационном режиме сеть для модели не используется. Наличие ключа на
экране соединений означает только настройку: кнопка проверки отдельно проверяет OAuth,
а генерация проверяется фактическим запуском агента.

## 8. Как работает поиск и остальные роли

После завершения карточки без вопросов запускается `SearchPipeline`.
Если вопросов ещё нет ответа, поиск откладывается, чтобы не потерять уточнения.

| Этап | Базовая реализация | Что улучшает владелец роли |
|---|---|---|
| 2. Планирование | Один тематический запрос по объекту и площадке | Несколько запросов, фильтры, пере-планирование, полнота |
| 3. Исследование | До 3 дел, PDF и дословные цитаты | OCR, акты всех инстанций, распознавание доводов и выводов |
| 4. Сравнение | Применимость high/medium/low/unknown, совпадения и отличия | Юридические признаки, качество ранжирования, контрпримеры |
| 5. Критика | Замечания к сравнению и достаточности материалов | Возврат на поиск, оценка противоположной практики |
| 6. Отчёт | Краткое резюме и следующие действия | Более строгая привязка каждого вывода к доказательствам |

В режиме GigaChat у каждой роли отдельная инструкция и тип результата.
Разрешены `inspect_context` и `submit_result`. Модель выбирает действие;
ошибка схемы возвращается ей для исправления. Лимит — 4 шага на роль.
Это минимальная агентная реализация, а не окончательные самостоятельные исследователи.

В demo и в режиме Alice AI эти последующие роли работают по базовым правилам,
без модельного юридического анализа. Alice AI полноценно подключена только к агенту 1.

Поиск обращается к `/parser/ras_arbitr_api/search`, чтение акта — к
`/parser/ras_arbitr_api/pdf_download`. Запросы к источнику ограничены восемью на запуск,
успешные ответы кешируются на 24 часа. Обрабатывается первая страница выдачи,
дубликаты объединяются по номеру дела. Полнота всех актов дела не гарантируется.

PDF сохраняется в ответе кеша, текст извлекается по страницам через pypdf.
PDF без текста получает явное сообщение «требуется OCR».
Модель получает до четырёх страниц каждого акта, до 5000 символов на страницу.
Проверка цитаты требует совпадения ID дела, номера страницы и точной подстроки.

Ссылки разрешены только на HTTPS-адреса КАД и Банка решений. Тексты выводятся
через `textContent`, а не через вставку произвольного HTML.

## 9. Что делать при недоступности Parser API

В форме «Библиотека судебных актов» укажите номер, суд, ссылку и вставьте текст
документа. Такой материал будет помечен как пользовательский импорт; система
не утверждает, что сверила его с оригиналом. Разрывы страниц задаются символом
form feed; без них весь вставленный текст считается одной условной страницей.

Локальная библиотека доступна для поиска без Parser API. В онлайн-режиме система
пытается дополнить её внешней выдачей. Ошибка источника остаётся предупреждением
в отчёте и не подменяется сообщением об отсутствии судебной практики.

Оба предоставленных ключа на момент проверки получили код 40301 на КАД и RAS.
Это ответ Parser API «недействительный ключ». Код ограничений IP у поставщика — 40303.
Причина на стороне аккаунта не установлена; смена IP не проверялась.

## 10. Очередь, восстановление и уточнения

`POST /api/runs` сохраняет задание и возвращает ID. `Idempotency-Key` защищает
от двойного нажатия: одинаковый ключ и ввод возвращают прежний ID, другой ввод
с тем же ключом отклоняется.

Worker получает задание на ограниченную аренду и продлевает её heartbeat.
Запись результата разрешена только текущему владельцу. После истечения аренды
задание можно подобрать повторно, сохранив контрольную точку. После трёх попыток
восстановления оно завершается ошибкой.

В PostgreSQL короткие операции создания/получения используют advisory lock.
Сетевые запросы и модель выполняются вне транзакции. SQLite сохранена для быстрых
изолированных тестов и автономной демонстрации.

После ответа на уточнение создаётся новый запуск с `parent_id`, прежний результат
остаётся в истории. Никакие прошлые клиентские сведения не переписываются молча.
Ошибка этапов поиска сохраняет успешную исходную карточку и частичный отчёт.

Остановка между внешним API-запросом и сохранением контрольной точки может привести
к повторному запросу после восстановления. Гарантии «ровно одно списание» нет.

## 12. Тесты

```powershell
.\.venv\Scripts\python.exe scripts/test_all.py
```

Скрипт запускает Ruff и pytest. При наличии DATABASE_URL автоматически включает
реальные PostgreSQL-тесты. Каждый такой тест создаёт уникальную тестовую схему
и удаляет только её. Таблицы приложения не очищаются.

Последний полный прогон: 54 проверки пройдены, включая реальный PostgreSQL и браузер.

- `tests/test_agent.py`: инструменты, цитаты, пробелы, конфликты, лимиты, адаптер Alice AI.
- `tests/test_backend.py`: API, очередь, идемпотентность, восстановление, согласие, ограничения ввода.
- `tests/test_integrations.py`: протокол GigaChat, вложенные схемы, кеш токена,

Обычные тесты не вызывают платные внешние API. Реальные вызовы выполняются только
